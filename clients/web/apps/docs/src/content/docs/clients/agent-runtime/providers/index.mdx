Corvus supports a wide range of AI providers, including both cloud-based and local options. You can configure your preferred provider during the onboarding process or by editing your `config.toml` file.

## Regional & Specialized Providers

Corvus also supports several regional and specialized providers, particularly for the Chinese market:

- **Moonshot (Kimi)**: `moonshot`, `moonshot-intl` (`MOONSHOT_API_KEY`)
- **GLM (Zhipu)**: `glm`, `glm-cn` (`GLM_API_KEY`)
- **MiniMax**: `minimax`, `minimax-cn` (`MINIMAX_API_KEY`)
- **Qwen (DashScope)**: `qwen`, `qwen-intl`, `qwen-us` (`DASHSCOPE_API_KEY`)
- **Qianfan (Baidu)**: `qianfan` (`QIANFAN_API_KEY`)
- **Z.AI**: `zai`, `zai-cn` (`ZAI_API_KEY`)

## Custom Endpoints

If you have a self-hosted or OpenAI/Anthropic-compatible API, you can use a custom provider string:

- **OpenAI-compatible**: Use `custom:<URL>` as the provider name.
- **Anthropic-compatible**: Use `anthropic-custom:<URL>` as the provider name.

Example:
```bash
corvus onboard --provider "custom:http://localhost:1234/v1" --api-key "your-key"
```

## Credential Resolution

Corvus resolves credentials in the following order:

1. Explicitly provided `api_key` in `config.toml`.
2. Provider-specific environment variable (e.g., `ANTHROPIC_API_KEY`).
3. Generic fallback environment variables (`CORVUS_API_KEY` or `API_KEY`).
