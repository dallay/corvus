# Product Contract: Local Custom Skills UX

## Overview

Local custom skills are user-authored skills that live within the Corvus workspace. They are the primary way users extend agent behavior with project-specific or personal instructions. Local skills always carry the **Local** trust tier — the highest trust level, equivalent to the user's own code.

This contract defines the directory layout, file format, installation methods, validation rules, and CLI experience for local skills.

## Directory Layout

Skills live under the workspace skills directory:

```
~/.corvus/workspace/skills/
├── my-skill/
│   └── SKILL.md
├── another-skill/
│   ├── SKILL.md
│   └── reference/
│       └── patterns.md
└── README.md          # Generated by `corvus init`
```

Each skill is a directory containing at minimum a `SKILL.md` file. Additional files (reference material, templates, scripts) are allowed and loaded on demand.

## SKILL.md Format

Every skill is defined by a `SKILL.md` file with optional YAML frontmatter:

```markdown
---
name: my-skill                    # Required — must match directory name
description: Brief purpose        # Required — shown in `skills list`
allowed-tools:                    # Optional — tools the skill may invoke
  - bash
  - read
version: 1.0.0                   # Optional — informational
author: username                  # Optional — informational
tags:                             # Optional — used for search/filtering
  - kotlin
  - testing
---

# My Skill

Full skill instructions go here. This content is injected into the agent's
prompt when the skill is activated.
```

**Frontmatter fields:**

| Field | Required | Description |
|-------|----------|-------------|
| `name` | Yes | Skill identifier, must match directory name |
| `description` | Yes | One-line description for listings |
| `allowed-tools` | No | Tool names the skill may use; triggers trust gate for ThirdParty |
| `version` | No | Informational version string |
| `author` | No | Informational author name |
| `tags` | No | List of tags for search and categorization |

## Installation

### Install from local path

```bash
corvus skills install ./path/to/my-skill
```

On Unix systems, this creates a **symlink** from the workspace skills directory to the source path. This means edits to the original directory are immediately reflected — ideal for skill development.

On Windows, the installer attempts a directory junction first, falling back to a full copy if junctions are unsupported.

### Skills created during init

Running `corvus init` creates the skills directory with a README template showing the expected layout and frontmatter schema. This gives new users a starting point for authoring their first skill.

## Commands

### List installed skills

```bash
corvus skills list
```

Shows all installed skills with name, version, description, and tags. Skills are grouped by trust tier in the output.

### Remove a skill

```bash
corvus skills remove my-skill
```

Deletes the skill directory (or removes the symlink) and removes the corresponding lockfile entry. Path safety checks prevent removal of directories outside the skills root.

## Validation

### On install

- Skill name must match the pattern `[a-z0-9-]`, between 1 and 64 characters, no consecutive hyphens (`--`)
- `SKILL.md` must exist in the skill directory
- YAML frontmatter is parsed if present; parse errors are reported but non-fatal
- Directory name must match the `name` field in frontmatter (if present)

### On load

- If the skill name doesn't pass validation, a **warning** is emitted but the skill still loads (backward compatibility)
- Integrity check runs against the lockfile hash (if entry exists)
- Scanner is **skipped** for Local skills — they are user-authored and trusted by definition

## Trust & Security

- Local skills always receive the **Local** trust tier
- Local trust cannot be escalated to Official (only catalog skills are Official)
- No trust gate is required for Local skills — installing a local skill is equivalent to writing code in your own project
- Local skills are not sandboxed; they have the same access as the user

## Limitations & Future Work

- **No `corvus skills init <name>` command** — users must manually create the directory and SKILL.md. A scaffolding command is a future nice-to-have.
- **No `--link` flag** — the installer auto-detects local paths and uses symlinks. An explicit flag for forcing symlink behavior is not currently needed.
- **No authoring guide** — beyond the README template, there is no dedicated documentation for skill authors. This should be added as the skill ecosystem matures.
